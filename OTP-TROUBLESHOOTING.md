# OTP Email Sending - Troubleshooting Guide

## Issue Summary
- Forgot password OTP is not being sent to email
- OTP may not be getting hashed properly in database

## What Was Fixed

### 1. ✅ OTP Hashing - VERIFIED
- The OTP service (`src/services/otpService.js`) **IS** hashing the OTP before storage
- Uses bcryptjs with salt rounds of 10
- Hash starts with `$2` (bcrypt format)
- **Added debug logs** to trace each step of OTP generation and hashing

### 2. ✅ Prisma Enum - VERIFIED  
- Added `ADMIN_PASSWORD_RESET` to `OtpType` enum in schema
- Prisma client has been regenerated with the new enum value
- Should now accept password reset OTP type without errors

### 3. ✅ Database Schema
- `otpVerification` table stores `otpHash` (not raw OTP)
- `type` field is now properly typed with OtpType enum

### 4. 🆕 Enhanced Logging
- Added console logs in `sendOtp()` function
- Added debug logs in `forgotPassword()` endpoint
- Check server console for detailed error messages

## Common Issues & Solutions

### Issue: "Invalid value for argument `type`. Expected OtpType"
**Solution**: Prisma client wasn't regenerated. The fix has been applied - the enum now includes ADMIN_PASSWORD_RESET.

### Issue: Email not being sent
**Possible Causes:**
1. **SMTP credentials not configured** - Check `.env` file has:
   - `SMTP_HOST=smtp.gmail.com` ✓ (already configured)
   - `SMTP_PORT=587` ✓ (already configured)
   - `SMTP_USER=your-email@gmail.com` ✓ (already configured)
   - `SMTP_PASS=your-app-password` ✓ (already configured)
   - `EMAIL_FROM="ITBEES Global <support@itbeesglobal.com>"` ✓ (already configured)

2. **Email service throwing error** - Check server logs for:
   ```
   [OTP] Error in sendOtp for admin@example.com: [error message]
   ```

3. **Gmail 2FA issue** - If using Gmail, must use:
   - App-specific password (not regular password)
   - Already configured in `.env`

### Issue: OTP showing raw value in database
**This should NOT happen** because:
- `sendOtp()` hashes the OTP with bcryptjs BEFORE storing
- Only the hash is stored in `otpHash` field
- The raw OTP is only shown in the email body

If you see raw OTP values, it means the code is NOT running through the normal flow.

## Database Schema

### OtpVerification Table
```
id              UUID (primary key)
email           String (the user's email)
otpHash         String (bcrypt hash - looks like $2b$10$...)
type            OtpType enum (PURCHASE, REGISTRATION, ADMIN_PASSWORD_RESET)
expiresAt       DateTime (5 minutes from creation)
attempts        Int (failed attempt counter, max 3)
isVerified      Boolean (marked true after successful verification)
createdAt       DateTime (when OTP was created)
```

## Flow Diagram

```
1. Admin requests forgot password
   ↓
2. forgotPassword() endpoint is called
   ↓
3. Admin email is looked up in database
   ↓
4. If found: sendOtp() is called with ADMIN_PASSWORD_RESET type
   ↓
5. OTP is generated (6-digit random number)
   ↓
6. OTP is hashed using bcryptjs ($2b$10$...)
   ↓
7. Hash + email + type + expiry stored in otpVerification table
   ↓
8. Raw OTP is sent to admin's email (nodemailer)
   ↓
9. Admin receives 6-digit code in email
   ↓
10. Admin enters OTP at frontend
    ↓
11. verifyOtp() checks: raw OTP against stored hash
    ↓
12. If match: OTP marked as verified, password can be reset
```
